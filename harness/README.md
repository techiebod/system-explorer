# The harnesses

Three judges, built before the things they judge (PLAN phase 1). Each checks
the outside of a process, so none of them cares what language anything was
written in.

## 1. Replay — `se_harness.replay`, driven by `conformance/test_corpus_replay.py`

Same payloads in, same records out.

**The seam is an environment variable.** Set `SE_REPLAY_DIR` and a collector
reads its native documents from that directory instead of from the live
interface, and does everything else unchanged — production parse, declared
redactions, stream generation. Only the acquisition call is redirected.

That is the whole contract. It is language-neutral, it needs no test-only code
path inside a collector, and it cannot drift from production behaviour because
it *is* production behaviour with one input swapped.

`SE_REPLAY_NOW` pins the wall clock to the moment of capture. Some facts are
derived at acquisition against *now* — a scrub's age in days, a snapshot's age
in seconds — and replayed against a live clock they change daily, so a corpus
pair would rot and the harness would teach a reader to ignore it. Pinning
states the moment rather than pretending there isn't one.

**What replay tolerates, and why.** Records are compared by identity, not
position: stream order is not significant (DESIGN 19), so a reordering must not
read as a defect. Run-varying fields are normalised out — monotonic `at`
readings, collator-issued `request`/`batch`, `boot_id`, measured cost. Every
other byte is a claim and is compared.

## 2. Collator — `harness/collator/*.json`

Recorded streams in, minted ids and joins and observabilities and opinions out.
Fully deterministic given its inputs, which is why it can assert things no
replay can: that two instances of one application never merge, that a
generation cannot roll state backward, that an unresolved endpoint becomes an
`asserted` relation rather than disappearing.

The fixture format is committed now and its loader is self-tested; **it has no
driver until the collator exists** (phase 2). That is stated rather than
stubbed, because a harness that passed while driving nothing would be the
failure this product is about.

## 3. Crash — `harness/crash/boundaries.json`

Kill a process at each boundary and require all-or-nothing. The boundaries are
enumerated now because they are a property of the protocol, not of the
implementation, and writing them down is what stops the list becoming "the ones
somebody remembered". Wires up in phase 2 alongside the collator.

## Capturing

    harness/bin/se-capture-guest <ssh-target> <collector>   # native payloads from a lab guest
    harness/bin/se-capture --write corpus/<collector>/<variant>   # the expected half

The expected half is generated by the reference implementation — the shipping
agent, which a ported collector must reproduce (PLAN rule 4) — and then **read
by a person before it is committed**. `se-capture` prints a diff and refuses to
write without `--write` for exactly that reason: a corpus that regenerated
itself silently would ratify the first regression that landed.
